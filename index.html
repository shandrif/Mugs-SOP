Mugs SOP Monitor

Limit of 2 mugs of one colour per customer, checked per branch

Drop the daily “Sales By Product” export here or (.xlsx, .xls, .csv) The file is processed in your browser only. Nothing is uploaded to any server.

What this flags

Direct violation

One invoice has more than the limit of the same colour, e.g. 6 × Al-Haram Beige.

Split-invoice run

The same branch rings the same colour on back-to-back invoices, each within the limit, that together go over it. Scored against that branch’s normal pace so busy branches aren’t over-flagged.

Zero-qty lines

Lines with 0 quantity / SAR 0, likely voids or returns, listed for review.

How the checks work

1. Rebuilding invoices

The export has no invoice number, so lines with the same branch + closing time (to the millisecond) are treated as one invoice. If a future export includes an invoice/receipt column, it is used automatically.

2. Direct violations

Any invoice with more than the limit of one item (or colour, depending on the setting).

3. Split-invoice runs

For each branch and colour, invoices are put in time order. Invoices no more than the max gap apart are chained into a run. A run is flagged when it has at least the minimum number of invoices, every invoice is within the limit, and the run total is over the limit.

4. Risk score (0–100)

  • Invoices in run up to 30 pts (5 per extra invoice)
  • Mugs over the limit up to 25 pts (2.5 per mug)
  • Burst vs normal up to 30 pts: how many times faster this branch sold this colour during the run than its normal pace for the rest of the day. A busy Haram branch selling quickly scores low; a quiet branch suddenly ringing 20 invoices in 10 minutes scores high.
  • Identical baskets up to 15 pts: share of invoices in the run with exactly the same contents (runs of 3+).

High ≥ 60, Medium 35–59, Low < 35.

Limits of this version

Without a card token, customer mobile or cashier ID in the export, a split run is likely, not proven: a real queue of different customers can look the same. Use the run detail to check with the branch, and the CCTV/POS logs for High runs.
